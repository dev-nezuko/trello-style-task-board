# Mini Trello: React, GraphQL and DynamoDB Local

A small shared task board with three columns: **To-Do**, **In Progress** and **Done**. React renders the cards, Django exposes a GraphQL endpoint, and DynamoDB Local stores card data. Create, edit, delete and move cards between columns.

This repository and [`kanban-project-board`](https://github.com/dev-nezuko/kanban-project-board) are overlapping copies of the same upstream demo. Keep one as the portfolio representative; they do not demonstrate two separate system designs. The other copy contains the more recent UI and mutation-validation improvements.

## Run locally

Requires Docker with Compose. The frontend image uses Node 18; backend requirements still declare Django 3.2, and have not been modernized here.

```sh
git clone https://github.com/dev-nezuko/trello-style-task-board.git
cd trello-style-task-board
cp .env.example .env
docker compose up --build
```

Open [the board](http://localhost:3000) or [GraphiQL](http://localhost:8001/graphql/). Published ports bind to loopback. Containers use `http://dynamodb:8000`; this hostname is not a host-machine endpoint. The entrypoint creates the `Card` table if missing and accepts an existing table on restart. Startup still relies on DynamoDB being ready; retry the backend if the first startup races the database.

The default debug mode creates an ephemeral signing key. Set a private `DJANGO_SECRET_KEY` before setting `DJANGO_DEBUG=0`. Do not reuse a key from old commits. Any previously deployed signing key or collection access key must be rotated by its owner; deleting Git history cannot revoke credentials or remove external caches.

## API example

The frontend calls `/graphql/` on port 8001. Graphene exposes camelCase field names:

```graphql
query Board {
  allCards { id title description status }
}
```

```graphql
mutation AddCard {
  createCard(title: "Review the setup", description: "Check local containers", status: "todo") {
    card { id title description status }
  }
}
```

`mini_trello_fe/src` contains the board and modal. `mini_trello_be/boards/schema.py` defines mutations; `models.py` is a boto3 wrapper, not a Django ORM model. SQLite supports Django's framework tables, while cards use DynamoDB.

## Boundaries and review notes

- This is a local single-board demo. It has no user login, board-level permissions or tenant isolation; its GraphQL view is CSRF-exempt. Do not expose it as a hosted service.
- Dragging within a column changes local order, without storing an ordering field. DynamoDB scans are not paginated, so this is suitable for a small demo dataset.
- Mutation errors and missing cards need more defensive handling. Empty descriptions cannot currently clear existing text. The improved sibling copy addresses several of these issues.
- The copied Python environment, generated bytecode and empty SQLite file were removed. Install from declared requirements instead of using a committed environment.
- No full Docker, DynamoDB or browser integration run was performed for this copy. Existing screenshots are not evidence that its current containers started successfully.
